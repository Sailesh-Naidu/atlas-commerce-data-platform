# BS-001: Trunk-Based Development with Short-Lived Branches

Status: Accepted

## Rule

Atlas uses `main` as the single long-lived branch.

All implementation work must occur in short-lived branches created from
the latest version of `main`.

Changes are merged back into `main` through pull requests.

## Branch Types

### Feature Branches

Used for new platform or domain capabilities.

Examples:

```text
feature/config-framework
feature/customer-snapshot
feature/order-streaming
```

# Commit message standard

We’ll use **Conventional Commits**.

Examples:

```text
feat(config): add layered configuration loader
fix(logging): prevent duplicate handlers
docs(hld): add observability architecture
test(customer): add schema validation cases
refactor(spark): separate session configuration
perf(order): reduce shuffle during deduplication
build(platform): configure uv and Ruff
chore(repo): update ignored local files
```
