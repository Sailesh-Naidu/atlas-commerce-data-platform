# DS-001: Module and Function Documentation

Status: Accepted

## Module Documentation

Every production module must include a module-level docstring
describing:

- purpose
- responsibilities
- related business domain
- related ADRs
- related HLD sections (when applicable)

The module docstring should explain why the module exists rather than
how it is implemented.

## Function Documentation

Every public function must include a docstring describing:

- business purpose
- parameters
- return value
- exceptions raised
- important assumptions
- usage notes (where appropriate)

Function docstrings should describe behaviour rather than
implementation details.

## Architecture References

Modules implementing architectural decisions should reference the
relevant ADRs and HLD sections.

This provides traceability between implementation and architecture.

## Type Hints

All public functions must use type hints as defined in CS-002.

Type hints complement docstrings by documenting the function contract.

## Rationale

Consistent documentation improves:

- onboarding
- maintainability
- code reviews
- architectural traceability
- long-term knowledge retention
