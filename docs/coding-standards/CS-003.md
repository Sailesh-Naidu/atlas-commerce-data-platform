# CS-003: Exception Handling

Status: Accepted

## Rule

Atlas must catch only exceptions that it can handle meaningfully.

Generic exception handling should be avoided unless it forms part of a
top-level safety boundary.

Exceptions must never be silently ignored.

## Logging

Every logged exception must include sufficient operational context.

Typical context includes:

- domain
- pipeline
- layer
- run identifier
- environment
- dataset
- operation
- exception details

Sensitive information must never be written to logs.

## Error Propagation

Exceptions that cannot be recovered from must be re-raised after logging.

The platform must fail fast rather than continuing with an inconsistent
business state.

## Recovery

Recoverable exceptions should trigger appropriate retry or recovery
mechanisms.

Non-recoverable exceptions should terminate the current pipeline
execution and notify Operations.

## Rationale

This approach improves:

- debugging
- observability
- operational support
- production reliability
- incident response

## Trade-offs

The platform may terminate earlier rather than attempting partial
processing.

This trade-off is accepted because business correctness is prioritized
over partial success.
