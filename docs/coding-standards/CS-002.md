# CS-002: Type Hints

Status: Accepted

## Rule

All production functions, public methods, job entry points and shared
platform interfaces must declare parameter and return types.

## Rationale

Type hints improve:

- readability
- IDE support
- refactoring safety
- static analysis
- onboarding
- interface clarity

## Spark Consideration

A Spark DataFrame type annotation does not replace schema validation.

Python type contracts and data contracts are separate responsibilities.

## Exceptions

Type hints may be omitted from:

- exploratory notebooks
- disposable experiments
- obvious local variables

## Trade-offs

Type hints add verbosity and may become difficult to read when interfaces
are overly complex.

Complex types should be replaced with named models or type aliases where
appropriate.
