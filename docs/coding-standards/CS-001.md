# CS-001: Single Responsibility Functions

Status: Accepted

## Rule

Every function must have a single, clearly defined responsibility.

A function should answer one question and perform one logical operation.

Functions should be composed together to implement larger business
workflows.

## Naming

Function names must clearly describe their purpose.

Avoid generic names such as:

- process()
- execute()
- run()
- handle()
- transform()

Prefer business-oriented names such as:

- validate_customer_schema()
- normalize_customer_email()
- remove_duplicate_customers()
- apply_customer_scd2()

## Function Composition

High-level orchestration functions should read like business workflows.

Example:

```python
customer_df = read_snapshot()

customer_df = validate_schema(customer_df)

customer_df = normalize_customer(customer_df)

customer_df = apply_business_rules(customer_df)

customer_df = deduplicate(customer_df)

customer_df = apply_customer_scd2(customer_df)

write_customer(customer_df)
```

The orchestration function coordinates the workflow.

Each helper function owns one business responsibility.

## Rationale

This approach improves:

- readability
- maintainability
- testability
- code reviews
- debugging
- reuse

## Trade-offs

This approach introduces:

- additional functions
- additional files
- greater importance of good naming

These trade-offs are acceptable because long-term maintainability is
more valuable than reducing the number of function calls.
